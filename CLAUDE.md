# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Test Commands

```bash
# Build debug APK
./gradlew assembleDebug

# Build release APK (requires signing config in local.properties)
./gradlew assembleRelease

# Run lint checks
./gradlew lint

# Run unit tests
./gradlew test

# Run a single test class
./gradlew test --tests "rj.kilikili.utils.encode.MD5UtilTest"

# Build project
./gradlew build

# Clean
./gradlew clean
```

JDK 17 required. Gradle properties optimized with parallel execution, ZGC, and R8 incremental builds.

## Project Structure

**KiliKili** is a third-party Bilibili client for Wear OS (Android smartwatch), currently being rewritten on the `rewrite` branch with Jetpack Compose and Material3.

### Modules

| Module | Purpose |
|--------|---------|
| `app` | Main application module |
| `BiliWebApi` | Bilibili API client wrapper (OkHttp/Retrofit-based) |
| `ijkplayer-java` | ijkplayer native video player bindings |
| `DanmakuFlameMaster` | Danmaku (bullet comment) overlay rendering |
| `brotlij` | Brotli compression bindings |
| `NativeBitmap` | Native bitmap operations |

### App Architecture (`app/src/main/java/rj/kilikili/`)

```
api/           - Bilibili API client (BiliWebApi adapter, cookie management, WBI signing)
data/
  account/     - Multi-account management, cookie persistence via Room
  database/    - Room database (AppDatabase.kt with single table)
  di/          - Hilt DI modules (ApiModule, DatabaseModule, NetworkModule)
  download/    - Download management (WorkManager-based)
  menu/        - Configurable navigation menu system
  paging/      - Paging 3 data sources
  repository/  - ~30 repositories (VideoRepository, RecommendRepository, etc.)
  setting/     - Settings persistence (DataStore + Proto DataStore via AppSettingsSerializer)
event/         - EventBus events
ui/
  activity/    - Single-activity: MainActivity extends BaseActivity
  animations/  - Shared transition animations
  common/      - Shared composables (CustomSnackbarHost, etc.)
  components/  - Reusable UI components (menu panel, etc.)
  dialog/      - Dialog composables
  navigation/  - NavHost, route definitions (AppNavHost, Routes, LoginGraph, SettingsGraph)
  screens/     - Feature screens (~27 features: recommend, video, player, dynamic, search, etc.)
  theme/       - Material3 theming (19 color schemes, light/dark, Theme.kt, Color.kt)
  viewmodel/   - Shared ViewModels
  widget/      - Custom widgets (RecyclerView adapters, wearable-specific components)
utils/         - Utilities: API helpers, debug tools, diff utils, encoding, extensions, locale, network
worker/        - WorkManager background workers (download service)
```

### Navigation Architecture

Three-level navigation using Wear Compose's `SwipeDismissableNavHost`:

1. **SetupGraph** → First-launch setup wizard
2. **LoginGraph** → QR code login flow (with skip option)
3. **MainGraph** → Content navigation with configurable menu panel (slide-in drawer)

The main screen has its own inner `SwipeDismissableNavHost` for feature navigation, with a `MenuPanel` overlay that slides in from the left.

### Screen Pattern

Each feature follows this convention:
- `ui/screens/<feature>/` - Contains Screen composable and ViewModel
- Screens are composable functions receiving navigation callbacks as parameters
- ViewModels use Hilt injection for repositories
- Repositories wrap BiliWebApi calls with `apiResultNonNull()` / `apiResult()` extension functions that convert `ApiResponse<T>` to `kotlin.Result`

### API Layer

- `BiliWebApi` library module wraps Bilibili HTTP APIs with WBI signing
- `bilibiliApi` singleton in `api/BilibiliApi.kt` manages OkHttp client, cookies, SSL
- Cookie management uses Hilt-injected `AppCookieManager` with multi-account support via Room
- API result handling uses sealed `BilibiliApiException` for structured error handling

### Theme System

- 19 Material3 color schemes generated by `materialThemeBuilder` Gradle plugin
- Dynamic theme overlay with light/dark modes per color
- Theme selector in UI settings screen
- Custom `BiliZepamTheme` composable in `ui/theme/Theme.kt`

### Build Config

- Version from `version.properties` + git commit count + git hash
- ABI splitting for armeabi-v7a, arm64-v8a, x86, x86_64
- Release builds: R8 minification + resource shrinking
- Debug builds: `BETA=true` build config field
- Proto DataStore for settings serialization
- `autoResConfig` plugin for locale generation
- Lint baseline at `app/lint-baseline.xml`

## Testing

- Only JVM unit tests exist — `app/src/test/` and `BiliWebApi/src/test/`. No `androidTest/` sources.
- `./gradlew test` runs **all** module test tasks. Be specific to keep CI signal high:
  - Single test class: `./gradlew :app:testDebugUnitTest --tests "rj.kilikili.utils.encode.MD5UtilTest"`
  - Single test method: `./gradlew :app:testDebugUnitTest --tests "rj.kilikili.utils.encode.MD5UtilTest.someMethod"`
  - All tests in a module: `./gradlew :BiliWebApi:test`
- Lint baseline lives at `app/lint-baseline.xml`; Android lint output goes to `app/build/reports/lint-results-*.html`. The Gradle task is plain `./gradlew lint` — there is no ktlint/spotless configured.

## Files agents must know about

- `version.properties` — versionName/versionCode source. Auto-suffixed with git commit count + hash at build time.
- `local.properties` — holds `MAPS_KEY` and signing key aliases/passwords. Don't print or commit changes.
- `key.jks` — release signing key, **checked into the repo**. Treat as compromised-key territory: do not rotate, do not re-export, do not print the password in logs.
- `app/proguard-rules.pro` — R8 keep rules (including for `BiliWebApi` DTOs and Hilt-generated code).
- `gradle.properties` — ZGC + parallel + R8 incremental + R8 maxWorkers=8 already on. `org.gradle.daemon=false` is intentional.

## Working tree gotchas

- The current branch is `rewrite` (per CLAUDE.md, the project is being rewritten on this branch with Compose + Material3). Do not assume `main` semantics; the module table and screen list reflect the rewrite state.
- `Orbit` and `PiliPlus` are **symlinks to external directories** (`~/Orbit`, `~/PiliPlus`). TODO.md uses them as comparison references. **Do not edit files reached through these symlinks** — changes there belong to those other repos, not this one.
- `app/src/main/.../api/BilibiliApi.kt` and `data/repository/BaseRepository.kt` are commonly modified; check `git status` before assuming the tree is clean.
- API result extensions referenced in the Screen Pattern section live at `app/src/main/java/rj/kilikili/data/repository/BaseRepository.kt` (`apiResultNonNull`, `apiResult`). `BilibiliApiException` is in `api/`.
- `BiliWebApi/` is a library module vendored in-tree. Treat it as a dependency surface — bump it in lockstep rather than reaching across modules with workarounds.

## Don't (this repo's specific landmines)

- Don't add `androidTest/` sources or instrumentation-only dependencies without confirming a target device — the project targets Wear OS, and CI has no device farm configured.
- Don't run `./gradlew --release` style flags; use the explicit `assembleDebug` / `assembleRelease` tasks to keep signing config predictable.
- Don't commit `local.properties` changes that print secrets to build logs.
